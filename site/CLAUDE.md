# Сайт «Ритм» (`site/`)

> Справка Claude по этой папке (загружается сама при работе с её файлами). Общие правила — в корневом CLAUDE.md.

- Сайт «Ритм» (привычки в стиле Grit + задачи/цели): исходник `site/ritm.html` (формат артефакта claude.ai, опубликован как https://claude.ai/artifact/Azqh8eJWCmDpzh3X3M54t5, данные в db-хранилище аккаунта). Версия-приложение для iPad (PWA, «На экран Домой»): `python3 site/build_pwa.py` собирает `docs/` (манифест, иконки, офлайн sw.js), публикуется на https://sawqws.github.io/123/ (GitHub Pages из ветки `gh-pages`; её сам обновляет workflow `.github/workflows/pages.yml` при изменении `docs/` в main); там данные в localStorage устройства, копия — «Итоги → Данные». После правки `site/ritm.html` пересобрать `docs/` и переопубликовать артефакт.
- Сайт «Калории» (счётчик КБЖУ + соль, Глеб 25.10: «как iPhone, минимализм, люкс»): `docs/kcal/` (один `index.html` + манифест, офлайн `sw.js` со своей областью `kcal/`), публикуется тем же workflow на https://sawqws.github.io/123/kcal/. Данные — localStorage устройства (копия — «Настройки → Данные»). Вид — Liquid Glass iOS 27 (Глеб 25.10: «в стиле самого последнего обновления Apple»): стекло только у навигации поверх контента (`.glass`: матовое, тёмный край, блик сверху; плавающее меню-капсула + круг «+», сжимается при прокрутке и раскрывается по нажатию; кнопки-круги в листах; низкие листы — стеклянные с отступом от краёв), контент непрозрачный; чёрный фон, белое кольцо калорий, неделя мини-кольцами, серия дней, списки радиусом 26, свайп «Удалить», пружинящие линзы сегментов. Проверка от А до Я — `node site/kcal_test.js [папка-скриншотов]` (195 проверок, сервер фото подменяется; при правке — дописывать сюда новые). Нормы по умолчанию — тренировка 3400 (Б130/Ж105/У485), отдых 2800 (Б125/Ж95/У360), соль ≤ 5 г, дни тренировок Пн Вт Ср Сб (по WHOOP). База `BASE` (продукты) и `DISHES` (популярные блюда ≈) — средние значения на 100 г, последняя цифра — соль. Еда по фото — сервер Тренера (`/api/kcal/pair` код из `/site` → токен, `/api/kcal/photo`, см. `coach/CLAUDE.md`); выбор файла открывается только по нажатию. База поиска — `docs/kcal/foods.json` (~7 тыс.: USDA FNDDS с русскими названиями `site/kcal_usda_ru.tsv` + оценки русской и мировой кухни `site/kcal_extra.tsv`, «≈»), сборка `python3 site/kcal_foods.py`; продукты магазинов — онлайн через Тренера `/api/kcal/shop` (Open Food Facts). Шрифт — ui-rounded (SF Pro Rounded на iPhone), запасной Nunito (Глеб 25.10: «помягче, поскруглённей»). Фото: до 3 снимков + подсказка, в ответе диапазон граммов и уверенность. «Размер порций» (Глеб 03.11: «порции сильно больше обычного»): `S.portion` — 1 обычные / 1,5 большие (по умолчанию) / 2 очень большие (`PORTIONS`; старые 1,1–1,3 → 1,5), умножает только порции из базы с `unit.scale` (порция, тарелка, миска, горсть, шампур), не штуки и не свои/с упаковки; уходит в sync (`portion`, сервер хранит в `kcal:goals`, отдаёт в state) и в `/api/kcal/photo` (подсказка модели `ai.plate_portion`). Быстрый завтрак (Глеб 03.11): капсулы `QUICK` над списком «Завтрака» и в листе «Добавить» при «Завтраке» — «Хлопья Nordic», «Рисовая каша», «Пшённая каша» (каша на молоке большой порцией + авокадо отдельной строкой, если его ещё нет), «Авокадо»; повтор — тост «уже в завтраке» с «Ещё раз», после добавления — «Отменить»; цифры и источник — комментарий у `QUICK`. Встроенная база разбита на разделы (строки-названия в `BASE`/`DISHES`, `grouped`), ~280 позиций; такие же названия из `foods.json` в поиске скрыты (`OWN`). Вода: `days[д].water` — список мл, норма `S.water` (расчёт 29.10: тренировка 3400, отдых 2500; `S.waterSet` — поменял сам, тогда своя), кнопки +250/+500/другое/отмена, в истории — среднее. Вкладка «Чат» (Глеб 25.10): вопрос + дневник дня (`chatContext`: норма, съедено, осталось, вода, порции, что ел) → `POST /api/kcal/chat` Тренера → ответ и до 5 блюд, их можно добавить в дневник одной кнопкой; переписка — `S.chat` (60); ответ приходит потоком (`stream: true`, text/event-stream, `paintLive`). Плавность (Глеб 25.10): анимация входа только при переходе (`.view.enter`), кольцо и полоски растут от прежнего значения (`shown.pct`, `shown.w`), вкладки — View Transitions, прокрутка — раз в кадр, размытие сверху только при прокрутке, снизу — без размытия, база блюд грузится заранее, поиск — через 90 мс после ввода; замер — CPU ×4. Все устройства (Глеб 29.10): ≥ 768 px — окна по центру (как на iPad), ≥ 960 px — «Сегодня» в две колонки (слева кольцо, БЖУ, вода; справа приёмы пищи), «История» сеткой, чат по центру; мышь — стрелки недели и подсветка под курсором; перед выкаткой `node common/devcheck.js` (11 размеров, обе темы). Иконки — `python3 site/kcal_icons.py`. После правки поднимать `CACHE` в `docs/kcal/sw.js`.
- «Калории» ↔ Форма (Глеб 01.11, договор `coach/SYNC.md`): при токене — `POST /api/kcal/sync` (14 дней, через 2 с после `save()`, при открытии/уходе), `GET /api/kcal/forma` → карточка «Форма» вверху дня (восстановление с точкой зоны, сон, нагрузка, тренировки, строка режима), тип дня авто из `train_today` (`ftype`, ручной `type` важнее), вода = своя + `water_forma`, еда «Из Формы» — только просмотр; вход по ссылке `#pair=<токен>` (из Формы «Открыть Калории»); 401 — «Связь с Формой потеряна». Вид — чёрно-белый (Глеб 01.11: только чёрный и белый; красный — только соль сверх нормы и удаление). `sw.js` не кэширует `/api/`. Проверок в `kcal_test.js` — 330.
- «Калории» внутри Формы (Глеб 01.11, `coach/SYNC.md` §5): `API` — на github.io сервер Формы, иначе `location.origin`. `?embed=1&theme=dark|light` (класс `embed` на `<html>`, ставится до отрисовки): нижнего меню нет — разделы сверху сегментами `#eseg` (фиксированы, линза едет; повторное «Сегодня» — к сегодняшнему дню), круг «+», листы и поле чата — над меню Формы (`--emb` = max(safe-area + 90, 110) px, на ≥ 1024 — 0); тема — `data-theme` из `theme=` и по сообщению `forma-theme` (только от `location.origin`); без своего service worker и без входа/«Связать» (401 → `parent.postMessage({type:'kcal-auth'})`); после `save()` — `kcal-changed`. Данные на любом устройстве: у дня `u` (строго растущее время правки; `stampDays` сравнивает слепок дня `dayKey` — еда, вода, ручной тип; `ftype` не правка); при старте с токеном `pullState` → `GET /api/kcal/state` → `mergeState` (у кого `u` больше — тот прав, пустой свой день уступает серверному, нормы/соль/вода — с сервера, если свои по умолчанию), потом sync; `stale` в ответе sync → снова state. Первая связка или нет `S.fullSync` — вся история (≤ 400 дней) кусками по 31 (`fullChunks`), потом флаг; обычный sync — 14 дней + давние дни с `u > S.syncU`. «Удалить все записи» при связи — пустые дни с новым `u`. Проверка: `node common/devcheck.js '<url>?embed=1&theme=dark'` и `--scheme light`.
