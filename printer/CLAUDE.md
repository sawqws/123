# Бот «Принтер» (Глеб, 08.11)

Личный бот 3D-принтера Creality Ender-3 V3 KE: сколько осталось, пауза, отмена, запуск файлов, остывание, сообщения о старте, первом слое, готовности, ошибке и пропаже связи.

- Код `printer/printer_bot.py` на `studio/kit/botkit.py`, pm2 `printer-bot`, секреты `/etc/printer-bot.env`, данные `printer/data/`. Тесты: `python3 printer/test_printer.py`.
- Связь: принтер дома за роутером, Telegram с него не открывается, а сервер открывается. Поэтому принтер сам держит обратный SSH-туннель (`printer/tunnel/setup.sh`, служба `/etc/init.d/S99printer_tunnel`, папка `/usr/data/printer-tunnel/` на принтере). На сервере `127.0.0.1:17125` — Moonraker, `127.0.0.1:17999` — штатный websocket экрана.
- Пользователь туннеля `printertunnel` на сервере: без shell, ключ ограничен этими двумя портами (`authorized_keys`), настройки в `/etc/ssh/sshd_config.d/printertunnel.conf`. Зависший туннель бот сбрасывает сам (`heal_tunnel`).
- Если принтер выключен, бот честно пишет «Нет связи». Во время печати сообщает о пропаже через 3 минуты.
- Запуск печати: `PRINTER_START=moonraker` (по умолчанию) или `screen` (`opGcodeFile` на websocket экрана). При запуске через Moonraker служба экрана держит `progress = 0, remain = 0`. Что запуск через `screen` это чинит — пока гипотеза, проверить на первой же печати.
- Вопросы (Глеб, 08.11): любой текст, голосовое и фото идут к Claude (`printer/ai.py`, правила и знания о принтере — `printer/prompt.md`, разговор живёт сутки, `/new` — заново). В каждый вопрос бот подставляет свежие данные принтера (`facts`, только чтение). Claude работает в `/var/lib/printer-bot/ai`, токены убраны из окружения, Bash нет, править может только `models/src/**`. Действия он предлагает метками `[[pause]]`, `[[file:имя]]`: бот показывает кнопку, нажимает Глеб.
- Модели и нарезка (`printer/slicer.py`): присланный `.stl` или модель от Claude становится карточкой с картинкой, размерами и кнопками «Нарезать» и «На стол». Claude пишет `models/src/имя.scad` или правит `models/src/organizers.html` и ставит `[[build:имя]]`; бот собирает, Claude смотрит картинку и при ошибке правит сам (`build_loop`, до 4 раз); `[[model:имя]]` показывает результат Глебу. Профили — `printer/profiles/` (копия с компьютера: баланс, прочнее, быстрее).
- Песочница (`printer/setup_slicer.sh`): OrcaSlicer собран под Ubuntu 24.04, сервер на 22.04, поэтому образ 24.04 в `/opt/orca/root` (1,3 ГБ) и запуск через bubblewrap: только чтение, без сети, виден один каталог задания, предел памяти, приоритет 19. Так же идут OpenSCAD и node, потому что правленый Claude код может быть любым. Не ставить в систему сервера пакеты без `NEEDRESTART_SUSPEND=1`: 08.11 `needrestart` перезапустил pm2 и всех ботов.
- G-code не передаётся на принтер, пока тот печатает или не на связи: передача по туннелю грузит слабый процессор принтера. Файл ждёт в `/var/lib/printer-bot/gcode`, `watch` кладёт его сам (`flush_pending`) и пишет Глебу. Запуск печати только кнопкой Глеба.
- Живая копия органайзера теперь на сервере: `/var/lib/printer-bot/ai/models/src/organizers.html`. Копия на компьютере (`~/Claude/organizers`) и 3D-просмотрщик не обновляются сами: после правок через бота их расходятся.
- Файлы: Telegram отдаёт ботам только до 20 МБ. Большой G-code кладётся с компьютера через Moonraker.
- Нажатия «Пауза», «Отмена», «Продолжить», «Печатать», «Остудить» действуют на настоящий принтер: при обходе кнопок и в проверках на идущей печати их не нажимать, для этого есть тесты на подделке `FakeMoon`. `botpress` без `force` их не жмёт (`RISKY` в `tgbot/actions.py`). `🔄 Обновить` безопасна, но попадает под `RISKY` из-за слова «обнов»: для проверки нужен `--force`.
- Аватар: `python3 common/avatar.py apply printer`. Бот лежит в папке Telegram «Bot» (id 207).
