# Бот HDP (`bot/`)

> Справка Claude по этой папке (загружается сама при работе с её файлами). Общие правила — в корневом CLAUDE.md.

- Тест через бота (Глеб, 15.10: «максимально быстро сделать, не отправлять, написать, что сдаст позже»): Claude запускается с `HORO_DEFER=1` — `submit.js` вносит ответы без пауз и НЕ сдаёт (`horo/tmp/<task>/defer.json`); бот пишет «🧪 Тест решён — сдам в ЧЧ:ММ» (кнопки `tnow:`/`tdrop:`) и сам сдаёт по таймеру (`finish_test`: `submit.js --continue-only` — в той же попытке: платформа хранит ответы только при сдаче (у отложенной попытки статус created, ответов 0, кнопка «Начать»), поэтому ответы вводятся заново; «Попробовать ещё раз» не жмёт; «уже сдан» — только если API показывает недавно закрытую попытку; «как человек» — через 20–45 с на вопрос, 1,5–6 мин; выкл — сразу), печатает «БАЛЛЫ: x/y» и «ПОПЫТКИ: n/m». Не 100% — Claude перепроверяет каждый вопрос (промпт `RETRY`, прошлые ответы — `answers_try1.json`; какой вопрос неверный, сайт не показывает — `checkResult: null`) и вносит вторую попытку сам, если после неё остаётся запасная; иначе кнопка `tretry:`. Тесты в ожидании — `tests` в `bot_settings.json`, видны в «⏳ Ожидание», переживают перезапуск (`resume_tests`). Claude прошлого запуска бота при старте добивается (`kill_orphans`, `horo/tmp/claude_groups.json`). Вручную `submit.js` сдаёт сразу, без пауз. «Обновить всех» в Главном ждёт, пока HDP досдаст (`wait_hdp`, до 15 мин). Тесты — `DeferTest`. Ответ учителю после «✅ Отправить» уходит не сразу, а через `HDP_SEND_DELAY` минут (по умолчанию 4-12, «0» — сразу): карточка «⏳ Отправлю в ЧЧ:ММ» с «⚡ Сейчас» (`now:<task>`) / «✖ Отменить» (`hold:<task>`), время — `send_at` в черновике, `sender_loop` раз в 20 с (`due_sends`), переживает перезапуск. Настройка «⏳ Отправка» (кнопка у поля ввода «⏳ Отправка: <режим>» в режиме чата, /send, «⚙️ Ещё»): задержка ответа учителю сразу / 2–5 / 4–12 / 15–40 мин (`send_delay` в settings.json, `sd:<v>`) и «🧪 Паузы в тестах» (`human`, `sd:tests`; выкл — `HORO_FAST=1` для Claude). На каждом черновике свой выбор: «✅ Отправить учителю» (по настройке), «⚡ Сразу» (`now:`), «⏳ С задержкой» (`later:`, даже если в настройке «сразу» — тогда 4–12), «🕐 Ко времени» (`atq:` → кнопки «через 30 мин / 1 ч / 2 ч / в 17:00…/ завтра 7:30» `at:<task>:<epoch>` или своё время текстом «19:40», «через 40 минут» — `parse_time`). `/delay [on|off]` — всё «как человек» разом; строка в настройках приложения — `/api/human`. Отправляя вручную из облака — тоже выждать несколько минут.
- Бот: установка на новый сервер (и перевод старой установки на main) одной командой `curl -fsSL https://raw.githubusercontent.com/sawqws/123/main/bot/install.sh | bash` (pm2, секреты в /etc/horo-bot.env, владелец — первый /start). `/update` тянет main. «🩺 Проверка» (/check) показывает, работают ли сайт, Claude и почерк. Токены и пароли в репозиторий не класть: он публичный.
- Бот, приложение (Mini App): кнопка «HDP» слева от поля ввода или /app. `bot/web.py` — сервер на 127.0.0.1:8788 + туннель cloudflared (адрес …trycloudflare.com меняется при перезапуске, бот сам обновляет кнопку; нет cloudflared — скачивает в `horo/tmp/bin`), пускает только владельца по подписи Telegram. `bot/webapp/` — интерфейс без сборки на общем kit (`common/webapp/kit.css|js`, акцент индиго): Задания (ссылка → «Решить и сдать» / «Только ответы», автотесты, черновик учителю с правкой текста), Оценки, Учителя, живой прогресс. Действия идут через те же функции, что кнопки чата (`run_task`, `run_all`, `submit_draft`), результат — и в приложение, и в чат. Данные: `horo/overview.js` (задания, оценки, комментарии за один вход) → `horo/tmp/overview.json`, обновляются раз в 2 мин при открытом приложении и после каждого решения.
- Бот, 🌐 сайт в браузере (`bot/site/`, `/site` в боте): вид как у horodigital.ru (профиль со статусами, «Мои предметы» → предмет → тема с теорией и заданиями по уровням, «Статусы по заданиям», «Успеваемость», комментарии), у каждого задания «⚡ Сделать» (тест: решить и сдать, с подтверждением) / «✍️ Написать» (черновик учителю) / «👁 Ответы», у каждой темы «📖 Подготовь меня» (1/5/10 мин → `/api/prep/run` с uuid темы) и «⚡ Автотесты темы». Сервер — тот же `bot/web.py` (`/site/…`), API то же, что у приложения, плюс `/api/site/theory` (теория темы целиком: `node horo/prep.js --theory <uuid>`, кэш 12 ч в `horo/tmp/site/`) и `/api/site/running` (какие задания решаются). Вход прямо в Safari (Глеб 19.10: «не хочу через браузер Telegram»): на странице входа «📲 Войти через Telegram» (`/site/api/login/request` → бот пишет «✅ Войти» `sitel:<id>` → страница ждёт `login/poll`, не больше 5 просьб за 10 мин) или код из 6 цифр из `/site` (`login/code`, 10 неверных за 10 мин — пауза); ещё — одноразовая ссылка `…/site/login?c=…` (15 мин) → cookie `hdp_site` на полгода (HttpOnly, Secure, SameSite=Lax; в `horo/tmp/site_sessions.json` только sha256); cookie действует только с заголовком `X-Site: 1` (защита от чужих страниц), выход — `/site/logout`. Адрес — `https://hdp.<ip-через-дефисы>.sslip.io` (Caddy планера → 8788, `/` там ведёт на `/site/`), пока он не отвечает — адрес туннеля; свой — `HORO_SITE_URL`. В темах (`horo/prep.js` → topics) у заданий есть `lvl`, `req`, `score`/`max`, `used`/`left`, у темы — `achieved`. Тесты — класс `SiteTest` в `bot/test_bot.py`. Зеркало (Глеб 19.10): ⏻ у правого края — выкл/вкл бота одним нажатием (`/_hdp/off|on`, cookie `hdp_plain`, «вкл» рисует guard.js); картинки `/store/t|p/<id>` платформа отдаёт по 5–11 с — зеркало держит их в `horo/tmp/mirror_cache/` (до 1 ГБ, файл до 12 МБ, видео и Range — мимо) и качает заранее по ссылкам из ответов API (`mirror.Store`); файлы сайта платформы `/student/assets|tinymce/*` — тоже там, сжатые, с `Cache-Control: immutable`, соседние скрипты качаются заранее (`ASSET`/`CHUNK`); каркас HTML (одинаковый для всех /student/…) и ответы API (настройки, предметы, темы, статистика) — сразу из памяти с обновлением в фоне (`Swr`, список `SWR`; задания, попытки, ответы, черновики, чаты — всегда свежие; действие в /api/education через зеркало (кроме отметок «прочитано»), кнопки бота (`WRITE`), конец решения и сдача теста сбрасывают память); Caddy сжимает hdp (`encode`); соединений с платформой — до 32; «💬 Пожелания» к заданию (кнопка рядом с «Написать»/«Решить», `wish` в `/api/solve`) и пожелания по умолчанию в ⚙️ (`wish` в settings.json, по умолчанию «текстовые ответы — максимально кратко», `WISH_DEFAULT`); в чате слова рядом со ссылкой — тоже пожелание (`wishes()` в prompt_for). Панель бота на зеркале обновляется без перерисовки (Глеб 19.10: «резко дёргается… сделай плавнее»): `swap()` в overlay.js сверяет DOM по месту (`sync`/`patch`, карточки с `data-key` появляются `hdpx-enter` и уезжают `hdpx-leave`, раскрытые `<details>` и поле ввода не трогаются); черновик с таймером или в отправке — компактная карточка «Уйдут учителю» (`queuedCard`), нажатия «Ко времени»/«Сейчас»/«Отменить» показываются сразу (`optimistic`), бот подтверждает следом. Чаты (Глеб 19.10: «плохо сделаны чаты»): на вертикальном экране от 760 px (iPad, Split View) платформа сворачивала список в кружки без имён (`@media (orientation: portrait)`) — в overlay.css при `html.hdpx-chat` полный список с именами, как на компьютере (классы — по началу имени `[class*="_chatSmall_"]`), кнопки бота на странице чатов бледнее. Пока Глеб пишет в поле платформы (фокус в поле или в iframe редактора), плавающая полоса и вкладки бота плавно прячутся (`html.hdpx-typing`, `typingState`). «В работе» (Глеб 22.10: «плохо сделано»): одна карточка `workCard` — что решается (иконка предмета, шаг, полоска, %, время) и очередь по номерам (больше 4 — «Ещё N»); данные — `site_work` в `/api/site/wait` (название и предмет из overview до того, как Claude открыл задание: `task_meta`/`task_title`). «⚡ Автотесты» (Глеб 22.10: «в других предметах и темах кнопка не должна уходить»): в «Сейчас» — по предметам из `overview.topics` (раньше — из 22 обязательных `tasks`, отсюда «нет»), кнопка у каждого предмета и «Сдать все»; тесты — все несданные (обязательные и по желанию, статус appointed/reworking/failed, есть попытки), запуск — `runAutos` (по одному `/api/solve`). Черновик с картинками (Глеб 22.10: «сделанный скрин — на видном месте, а не в картинках»): картинки грузятся сами (`loadFiles`) и стоят крупно на всю ширину карточки сверху (`.hdpx-shots`, нажатие — на весь экран); ответ только на картинках — поле текста спрятано под «＋ Текст учителю» (`addtext`). Самообновление (Глеб 22.10: на открытой до выкатки странице оставались старые кнопки): `/api/state` отдаёт `mv` (версия файлов зеркала), overlay.js сравнивает со своей `?v=` и при новой сам меняет себя (`upgrade`: старый экземпляр `S.dead`, новые css+js, открытая панель открывается снова; не во время ввода и вопроса). «⚡ Все автотесты (N)» по всем предметам (Глеб 22.10): в полосе внизу на главной, профиле, предмете (не в чатах) и сверху карточки «Автотесты» в «Сейчас» (`aall`); перед запуском статус каждого теста сверяется с платформой (`topicTasks(…, true)`), решённые и ждущие сдачи по таймеру (`tests` в `/api/state`) не берутся, а `run_task` такой тест второй раз не решает («Этот тест уже решён»). Несколько фото сразу (Глеб 22.10: «показывается один, второй только потом»): платформе по-прежнему по одному (guard.js, очередь), но все выбранные сразу видны в полоске «Загружаю фото: N из M» над полем ответа (`#hdpx-upq`: ✓ / крутилка / ⏳ с ✕ / ⚠), всё загрузилось — уходит. guard.js старее кнопок (после выкатки) — страница перезагружается сама на следующем переходе (`guardStale`). Срок темы: после `deadlineDate + extraDeadlineDays` платформа пишет «Прошел срок доработок…, отправка решений невозможна» — бот такие задания не решает (`topic_closed` через `mirror.get_json` в `run_task`, «⛔ Срок темы прошёл», «только ответы» можно), на сайте — плашка в теме, «⛔ Срок темы прошёл» в полосе, автотесты темы не считаются (`closedTill`, `extra` в prep.js).
- Бот, «⏳ Ожидание» (кнопка у поля ввода, /wait, в «⚙️ Ещё»; Глеб 15.10 «лист ожидания — что скоро отправится»): отправки учителю по таймеру — во сколько и через сколько, кнопки «⚡ <задание>» (`now:`) и «✖ Отменить» (`hold:`); что отправляется прямо сейчас (`SENDING`); черновики, которые ждут его «Отправить» (кнопки `send:`/`ed:`); задания в работе или в очереди (`running`); «🔄 Обновить» (`w:upd`) правит карточку на месте. Логика — `waiting`/`waiting_card`/`send_waiting` в `bot/bot.py`, тесты — `WaitTest`.
- Бот, «🎯 Подтверждения» (кнопка у поля ввода, /exams; Глеб 15.10): сначала выбор «2.0 / 3.0 / Все» (`exams_choice`, на кнопке — сколько не зачтено; `/exams 2` — сразу список), под списком «🔄 Обновить» и переход к другому уровню (`ex:2|3|all`, `ex:upd:<то же>`); все подтверждения и контрольные 2.0 и 3.0 по всем предметам из `overview.json` → topics (`EXAM` — «Подтверждение», «Контрольная», «Итоговая работа», «Unit test», «Test 2.0», «Тест на уровень», «Проверочная»; без «Подготовки к…»): уровень из названия «2.0/3.0» или `lvl`, сначала несданное (🔁 доработка с «35% из 85%», 📝 не сдано со сроком или «❗ срок был», 🕓 на проверке), зачтённое — свёрнутой цитатой; ссылки на задания; данные старше 10 мин и «🔄 Обновить» — свежие с сайта (`refresh_overview`). `prep.js` отдаёт у заданий `pct` (результат в %) и `pass` (порог зачёта). Логика — `exam_items`/`exams_messages`/`send_exams` в `bot/bot.py`, тесты — `ExamsTest`.
- Бот, «📖 Подготовка» (/prep, кнопка, «подготовь к проверочной по алгебре за 5 минут» текстом или голосом, вкладка в приложении): предмет → что прошли (темы за ~4 недели из `horo/prep.js`/`overview.json` → topics, математика делится на Алгебру «А…» и Геометрию «Г…»; теория из «Материалов» темы, условия итоговых заданий и вопросы сданных тестов — только GET API, попытки не тратит) → ⚡1 / 📝5 / 📚10 мин или своё ТЗ → `claude -p` по `bot/prep_prompt.md` (JSON) → конспект и вопросы с ответами под `<tg-spoiler>`, «🔁 Ещё вопросы», «📚 Подробнее». Логика — `bot/prep.py`, приложение — `bot/webapp/prep.js|css`.
- Бот, медиа: голосовое — как текст; фото без черновика — Claude ищет на нём задание (ссылку или название из списка несделанных) и предлагает «Решить и сдать» / «Только ответы», а условие без ссылки — «Решить по фото» (только показать); при черновике фото уходит в него. Видео и кружки: речь — как голосовое, кадры — как фото. Файлы — в `horo/tmp/inbox/`.
- Бот HDP решает несколько заданий сразу: ссылки можно слать подряд, до 3 одновременно (`HDP_PARALLEL`, память сервера 2 ГБ), остальные — «⏳ В очереди», то же задание дважды не запускается. Несколько ссылок в одном сообщении — каждое задание отдельно. Черновиков учителю может быть несколько сразу (`drafts` в настройках, старый `draft`/`draft_queue` переводится сам): у каждого своя карточка с кнопками `send:<task>` / `ed:<task>` («✏️ Править») / `drop:<task>`; правка (текст, голос, фото) идёт в черновик, на карточку или картинку которого Глеб ответил (`mids`), иначе в текущий (`draft_on`: последний показанный или «✏️ Править»). Правка словами при решении от руки идёт через Claude, который правит `draw.py` задания и перезапускает его — новые картинки приходят в чат; правки не занимают места решения (`edit_lock`). В приложении — карточка на каждый черновик. Сессия сайта `horo/tmp/state.json` пишется атомарно (`horo/lib.js`). Сам бот ничего не присылает (сводку убрали). Задания в работе записаны в `active` (settings.json): после перезапуска (`/update`, «Обновить всех») бот пишет «🔄 Продолжаю после перезапуска» и решает их заново (`resume_active`, не больше 2 раз подряд).
- Бот, задания с проверкой учителем: Claude пишет черновик в `horo/tmp/<task>/draft.txt` и картинки в `draft_files/`, бот показывает его Глебу; исправленный текст или свои фото заменяют черновик, «✅ Отправить» запускает `answer.js`. Правки копятся в `horo/tmp/style/edits.jsonl`, выводы из них — в `horo/tmp/style/style.md` (Claude читает его перед ответом). Тесты: `python3 bot/test_bot.py`, `python3 -m unittest horo/test_alphabet.py`.
- Бот, «🧪 Проверка сайта от А до Я» (Глеб 19.10): /sitecheck, «⚙️ Ещё» → «🧪 Проверка сайта», в панели на сайте ⚙️ → «Проверить» (`/api/site/check`). `bot/sitecheck.py` выдаёт вход в зеркало на время проверки (потом закрывает), `node bot/sitecheck.js <адрес> <out.json> [--orig] [--max 45]` обходит страницы платформы через зеркало (до 45, похожих адресов — не больше 4–14): ошибки JS и консоли, ответы 5xx/4xx API, оборванные запросы, битые картинки, вылезание вбок (компьютер, iPad 820, телефон 390), пустые страницы, выкидывание на вход, долгие запросы (>8 с), кнопки бота и каждая вкладка панели; с `--orig` то же на настоящей платформе — общие ошибки помечаются «платформа» (не наши). Ничего не меняет на платформе: все не-GET запросы к /api перехватываются, `updateReadPosition=true` → false, вопросы теста, попытки и отдельные чаты не открываются. Отчёт — `horo/tmp/sitecheck/last.json`, в чат — коротко с «🛠 Починить найденное» (`SUP.start` — Claude поддержки HDP с перечнем наших ошибок), «📋 Подробно», «🔁 Ещё раз». Тест — `test_sitecheck_runs_reports_and_logs_out`.
